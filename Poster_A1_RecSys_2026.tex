\begin{block}{1. Introducción}
La tarea de \textit{Automatic Playlist Continuation} (APC) consiste en recomendar canciones para extender playlists existentes de forma coherente con el contexto musical ya presente.

En escenarios reales, APC enfrenta dos tensiones: maximizar calidad de ranking y mantener diversidad/cobertura para evitar recomendaciones redundantes.

Este trabajo propone un enfoque reproducible y local, sin dependencia operacional de APIs externas. La idea es capturar señales de co-ocurrencia y contexto mínimo para producir recomendaciones coherentes, pero también útiles para exploración del catálogo.

La contribución principal es un protocolo completo de evaluación que combina exactitud, cobertura y análisis por segmentos sobre un mismo conjunto de playlists.
\end{block}

\begin{alertblock}{2. Pregunta de investigación y objetivos}
\textbf{Pregunta:} ¿Qué tan competitivo es un sistema APC local y reproducible de dos etapas frente a métodos secuenciales y colaborativos, al evaluar tanto accuracy como métricas beyond-accuracy?

\vspace{0.15cm}
\textbf{Hipótesis de trabajo:} la co-ocurrencia debe dominar la calidad estructural del ranking, mientras que el reranking local ayuda a sostener cobertura y diversidad.

\vspace{0.25cm}
\textbf{Objetivos:}
\begin{itemize}
  \item Evaluar rendimiento frente a baselines fuertes.
  \item Cuantificar aporte de cada señal mediante ablations.
  \item Analizar comportamiento por segmentos y casos cualitativos.
\end{itemize}
\end{alertblock}

\begin{block}{3. Datos y protocolo experimental}
\begin{itemize}
  \item Dataset Spotify Playlists (Kaggle) con muestra deterministica por hash.
  \item Ejecución principal: 30\% (63,851 playlists evaluadas).
  \item Ejecución de sensibilidad: 20\%.
  \item Esquema de evaluación: \textit{leave-last-out}, mínimo 3 canciones por playlist.
\end{itemize}
\end{block}

\begin{block}{4. Metodología propuesta}
\textbf{Two-Stage Hybrid}
\begin{enumerate}
  \item \textbf{Retrieval}: vecinos item-item por co-ocurrencia (normalización coseno).
  \item \textbf{Reranking}: fusión ponderada de cooc + popularidad + artista + nombre de playlist.
\end{enumerate}

\textbf{Definición de señal cooc:} \textit{cooc} corresponde a la frecuencia de co-ocurrencia de dos canciones dentro de una misma playlist; a mayor co-ocurrencia relativa, mayor afinidad estructural entre ítems.

La primera etapa reduce el espacio de búsqueda a candidatos plausibles; la segunda reordena con señales locales que ayudan a recuperar contexto y a suavizar sesgos de popularidad.

\textbf{Comparadores incluidos}
\begin{itemize}
  \item Sequential Markov (primer orden)
  \item Collaborative ItemKNN
  \item Random, Most Popular, Playlist Name Popular
\end{itemize}
\end{block}

\begin{exampleblock}{11. Análisis de resultados}
\begin{itemize}
  \item Markov lidera en calidad de ranking (MAP/nDCG).
  \item Two-Stage mantiene HitRate competitivo y mayor cobertura de catálogo.
  \item La ablación \textit{sin cooc} produce la mayor caída: cooc es la señal estructural clave.
  \item El método híbrido ofrece mejor balance entre exactitud y exploración del catálogo.
\end{itemize}

\vspace{0.08cm}
La lectura conjunta de las métricas sugiere que el modelo no solo acierta más o menos, sino que reordena mejor el espacio de recomendación cuando necesita cubrir perfiles menos frecuentes.
\end{exampleblock}

\begin{block}{17. Trabajo futuro}
\footnotesize

Evaluar estas variantes por segmento y por dominio musical ayudaría a medir estabilidad real fuera de la muestra actual.

\begin{block}{13. Evidencia cualitativa}
\textbf{Caso de acierto (perfil medium + head):} el modelo conserva coherencia musical y recupera recomendaciones cercanas al objetivo.

\vspace{0.18cm}
\textbf{Caso de error (perfil long + tail):} deriva hacia subgeneros cercanos, sin capturar identidad de nicho del target.

\vspace{0.18cm}
Estos casos muestran el patrón más estable del sistema: cuando existe suficiente huella de co-ocurrencia, el reranking refina bien; cuando el target es muy raro, faltan señales externas para desambiguar.
\end{block}

\begin{alertblock}{14. Decisión metodológica sobre LastFM}
LastFM se evaluo como enriquecimiento opcional, pero se excluyo del pipeline principal por latencia de API y reproducibilidad limitada a gran escala.

La evaluación final prioriza un protocolo \textbf{local, estable y repetible}.

En un póster final, esta decisión importa porque fija un mensaje metodológico claro: la validez experimental depende de que el sistema pueda volver a ejecutarse con las mismas entradas y sin costo operacional oculto.
\end{alertblock}

\begin{block}{15. Discusión y limitaciones}
\begin{itemize}
  \item El rendimiento disminuye en playlists largas con targets de cola larga.
  \item La ausencia de embeddings semánticos limita la capacidad de generalización en nichos.
  \item Existe un trade-off explícito entre diversidad extrema y precisión de ranking.
\end{itemize}

\vspace{0.04cm}
En consecuencia, el sistema es sólido como base metodológica, pero todavía sensible a escenarios donde la coherencia musical no puede inferirse solo con co-ocurrencia local.
\end{block}

\vspace*{\fill}

\begin{exampleblock}{16. Conclusiones}
\begin{enumerate}
  \item Two-Stage Hybrid es una base robusta y reproducible para APC.
  \item Comparadores fuertes (Markov/ItemKNN) son esenciales para una evaluación justa.
  \item Las métricas beyond-accuracy muestran trade-offs relevantes para despliegue real.
\end{enumerate}

\vspace{0.05cm}
En conjunto, el trabajo deja una evidencia clara: la mejora de ranking no debe evaluarse aislada de cobertura y diversidad, porque en APC ambas dimensiones son parte del objetivo final.
\end{exampleblock}
