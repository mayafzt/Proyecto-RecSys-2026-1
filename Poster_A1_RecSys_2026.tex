\begin{block}{1. Introduccion}
La tarea de \textit{Automatic Playlist Continuation} (APC) consiste en recomendar canciones para extender playlists existentes de forma coherente con el contexto musical ya presente.

En escenarios reales, APC enfrenta dos tensiones: maximizar calidad de ranking y mantener diversidad/cobertura para evitar recomendaciones redundantes.

Este trabajo propone un enfoque reproducible y local, sin dependencia operacional de APIs externas. La idea es capturar senales de co-ocurrencia y contexto minimo para producir recomendaciones coherentes, pero tambien utiles para exploracion del catalogo.

La contribucion principal es un protocolo completo de evaluacion que combina exactitud, cobertura y analisis por segmentos sobre un mismo conjunto de playlists.
\end{block}

\begin{alertblock}{2. Pregunta de investigacion y objetivos}
\textbf{Pregunta:} Que tan competitivo es un sistema APC local y reproducible de dos etapas frente a metodos secuenciales y colaborativos, al evaluar tanto accuracy como metricas beyond-accuracy.

\vspace{0.15cm}
\textbf{Hipotesis de trabajo:} la co-ocurrencia debe dominar la calidad estructural del ranking, mientras que el reranking local ayuda a sostener cobertura y diversidad.

\vspace{0.25cm}
\textbf{Objetivos:}
\begin{itemize}
  \item Evaluar rendimiento frente a baselines fuertes.
  \item Cuantificar aporte de cada senal mediante ablations.
  \item Analizar comportamiento por segmentos y casos cualitativos.
\end{itemize}
\end{alertblock}

\begin{block}{3. Datos y protocolo experimental}
\begin{itemize}
  \item Dataset Spotify Playlists (Kaggle) con muestra deterministica por hash.
  \item Ejecucion principal: 30\% (63,851 playlists evaluadas).
  \item Ejecucion de sensibilidad: 20\%.
  \item Esquema de evaluacion: \textit{leave-last-out}, minimo 3 canciones por playlist.
\end{itemize}
\end{block}

\begin{block}{4. Metodologia propuesta}
\textbf{Two-Stage Hybrid}
\begin{enumerate}
  \item \textbf{Retrieval}: vecinos item-item por co-ocurrencia (normalizacion coseno).
  \item \textbf{Reranking}: fusion ponderada de cooc + popularidad + artista + nombre de playlist.
\end{enumerate}

La primera etapa reduce el espacio de busqueda a candidatos plausibles; la segunda reordena con senales locales que ayudan a recuperar contexto y a suavizar sesgos de popularidad.

\textbf{Comparadores incluidos}
\begin{itemize}
  \item Sequential Markov (primer orden)
  \item Collaborative ItemKNN
  \item Random, Most Popular, Playlist Name Popular
\end{itemize}
\end{block}

\begin{exampleblock}{11. Analisis de resultados}
\begin{itemize}
  \item Markov lidera en calidad de ranking (MAP/nDCG).
  \item Two-Stage mantiene HitRate competitivo y mayor cobertura de catalogo.
  \item La ablacion \textit{sin cooc} produce la mayor caida: cooc es la senal estructural clave.
  \item El metodo hibrido ofrece mejor balance entre exactitud y exploracion del catalogo.
\end{itemize}

\vspace{0.15cm}
La lectura conjunta de las metricas sugiere que el modelo no solo acierta mas o menos, sino que reordena mejor el espacio de recomendacion cuando necesita cubrir perfiles menos frecuentes.
\end{exampleblock}

\begin{block}{13. Evidencia cualitativa}
\textbf{Caso de acierto (perfil medium + head):} el modelo conserva coherencia musical y recupera recomendaciones cercanas al objetivo.

\vspace{0.35cm}
\textbf{Caso de error (perfil long + tail):} deriva hacia subgeneros cercanos, sin capturar identidad de nicho del target.

\vspace{0.35cm}
Estos casos muestran el patron mas estable del sistema: cuando existe suficiente huella de co-ocurrencia, el reranking refina bien; cuando el target es muy raro, faltan senales externas para desambiguar.
\end{block}

\begin{alertblock}{14. Decision metodologica sobre LastFM}
LastFM se evaluo como enriquecimiento opcional, pero se excluyo del pipeline principal por latencia de API y reproducibilidad limitada a gran escala.

La evaluacion final prioriza un protocolo \textbf{local, estable y repetible}.

En un poster final, esta decision importa porque fija un mensaje metodologico claro: la validez experimental depende de que el sistema pueda volver a ejecutarse con las mismas entradas y sin costo operacional oculto.
\end{alertblock}

\begin{block}{15. Discusion y limitaciones}
\begin{itemize}
  \item El rendimiento disminuye en playlists largas con targets de cola larga.
  \item La ausencia de embeddings semanticos limita la capacidad de generalizacion en nichos.
  \item Existe un trade-off explicito entre diversidad extrema y precision de ranking.
\end{itemize}

\vspace{0.15cm}
En consecuencia, el sistema es solido como base metodologica, pero todavia sensible a escenarios donde la coherencia musical no puede inferirse solo con co-ocurrencia local.
\end{block}

\begin{exampleblock}{16. Conclusiones}
\begin{enumerate}
  \item Two-Stage Hybrid es una base robusta y reproducible para APC.
  \item Comparadores fuertes (Markov/ItemKNN) son esenciales para una evaluacion justa.
  \item Las metricas beyond-accuracy muestran trade-offs relevantes para despliegue real.
\end{enumerate}

\vspace{0.15cm}
En conjunto, el trabajo deja una evidencia clara: la mejora de ranking no debe evaluarse aislada de cobertura y diversidad, porque en APC ambas dimensiones son parte del objetivo final.
\end{exampleblock}
